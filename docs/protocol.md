# シリアルプロトコル / Serial Protocol（rev2 / fw v4.4）

AE-RP2040 ファーム（v4.4）のコマンド仕様。rev1（ESP32, v3）から追加・変更した点は **[v4]** / **[v4.1]** / **[v4.2]** / **[v4.4]** で示す。

| 項目 | 値 |
|---|---|
| 接続 | USB CDC（RP2040 ネイティブ USB、VID `0x2E8A`）。ドライバ不要 |
| ボーレート | **無関係**（何を指定しても USB Full Speed で転送される）。ただし **1200 は指定しない**（BOOTSEL に入る） |
| DTR | **ON にして開くこと**。arduino-pico は DTR が OFF だと送信データを捨てる |
| 改行 | `\r`、`\n`、`\r\n` のいずれでも可 |
| 大文字・小文字 | 区別しない |
| 数値 | アドレス・データ・`B` の長さは 16 進（`$` や `0x` は付けない）。`P`/`H` の個数、`S` の時間は 10 進 |
| 文字コード | 応答はすべて ASCII（`B` と `D` のデータ部だけバイナリ） |

---

## 起動時の状態

| 信号 | 状態 | 意味 |
|---|---|---|
| `CART_PWR_EN` | 0 | カート電源 OFF（VCC_CART = 0 V） |
| `BUS_EN_N` | 1 | U1〜U4、U9 の出力が Hi-Z |
| `OE_DATA_N` | 1 | U5、U6（データ書き込み用）の出力が Hi-Z |
| 制御線 | 非アクティブ | M2 = 0、/ROMSEL = 1、R/W = 1、/RD = 1、/WR = 1、/A13 = 1 |

PC がポートを開くと（DTR が立つと）一度だけ `Famicom Dumper rev2 (AE-RP2040) fw v4.4. cart power OFF. '?' for help` を表示する。

**カセットを読む前に必ず `O 1` を送ること。** `V` `P` `H` `M` `B` `D` `T` `W` `X` は、カート電源が OFF だと `ERR cart power off (send O 1 first)` を返す。

## コマンド一覧

### 電源・状態 [v4]

| コマンド | 動作 | 応答例 |
|---|---|---|
| `O 1` | カート電源 ON → 10 ms 待ち → /FLT = 1 かつ VCC_CART ≥ 4.0 V を確認 → `BUS_EN_N` = 0 | `PWR ON vcart=4951mV` |
| | 確認 NG のときは電源を切って終了 | `PWR NG vcart=812mV flt=1` |
| `O 0` | `OE_DATA_N` = 1 → 制御線を非アクティブ → `BUS_EN_N` = 1 → 電源 OFF → VCC_CART < 0.5 V まで待つ（最大 200 ms） | `PWR OFF vcart=466mV` |
| | 200 ms で放電しきれなかったとき | `PWR OFF vcart=1203mV (WARN: not discharged)` |
| `Q` | 状態表示 | `VCC_CART=4951mV  /FLT=1  power=ON  BUS_EN_N=0` |

- 電圧は mV 単位の整数で表示する（arduino-pico の `printf` は `%f` を表示できないため）
- `O 0` の値は「0.5 V を下回った最初の測定値」なので 0.45〜0.5 V 前後になる。警告が出なければ正常
- 動作中に /FLT（過電流）を検出すると、即座に `OE_DATA_N` = 1、`BUS_EN_N` = 1、電源 OFF にして `ERR overcurrent (/FLT) - cart power cut` を返す

### バス・信号の操作

| コマンド | 引数 | 動作 | 応答例 |
|---|---|---|---|
| `E n` | 0 / 1 | `BUS_EN_N` の設定（`O 1` / `O 0` が自動で行うので通常は不要）。電源 OFF で 0 にすると警告 | `BUS_EN_N = 0 (enabled)` |
| `A cccc pppp` | CPU アドレス（15 bit）、PPU アドレス（14 bit） | 595 にアドレスを出力して保持 | `CPU A=$7FFF  PPU A=$3FFF` |
| `C name n` | 制御線名、0 / 1 | 制御線を個別に設定。名前は `M2` `ROMSEL` `RW` `RD` `WR` `A13` | `M2 = 1` |
| `I` | なし | 制御線をすべて非アクティブに戻す | `control lines idle` |
| `R` | なし | 165 に現在のデータバスをロードして読む | `CPU D=FF  PPU D=FF` |
| `G` | なし | CIRAM A10、CIRAM /CE を読む | `CIRAM_A10=1  CIRAM_CE_N=1` |
| `T` **[v4]** | なし | データバス折り返し試験（下記） | `LOOPBACK OK` |
| `S [clk acc]` **[v4.1]** | ns、ns | バス駆動タイミングの設定・表示（下記） | 下記 |

### 読み出し

| コマンド | 引数 | 動作 | 応答例 |
|---|---|---|---|
| `V` | なし | CPU の割り込みベクタ（`$FFFA`〜`$FFFF`）を読んで判定 | 下記 |
| `P aaaa [n]` | 開始アドレス（`$8000`〜`$FFFF`）、バイト数（省略時 16） | PRG-ROM の 16 進ダンプ | `FFF0: 19 19 1A 1A …` |
| `H aaaa [n]` | 開始アドレス（`$0000`〜`$1FFF`）、バイト数（省略時 16） | CHR-ROM の 16 進ダンプ | `0000: 03 0F 1F 1F …` |
| `M` | なし | ミラーリング判定 | 下記 |
| `B P\|C aaaa nnnn` **[v4.1]** | 種別、開始アドレス、長さ（16 進） | ブロック読み出し（バイナリ）。**[v4.4]** `P` は `$6000`〜`$FFFF`（`$6000`〜`$7FFF` は PRG-RAM。/ROMSEL = H のまま読む） | 下記 |
| `D` | なし | NROM 全領域のバイナリダンプ（v3 互換形式） | 下記 |

### 書き込み [v4.2]

| コマンド | 引数 | 動作 | 応答例 |
|---|---|---|---|
| `W aaaa dd` | CPU アドレス（`$4020`〜`$FFFF`）、データ | CPU バス書き込み（マッパーのレジスタ設定） | `OK` |
| `X aaaa dd` | PPU アドレス（`$0000`〜`$1FFF`）、データ | PPU バス書き込み（CHR-RAM の判定） | `OK` |

`A` の CPU アドレスは下位 15 bit（A0〜A14）。A15 はコネクタに出ておらず、/ROMSEL がその役割を担う。`$8000`〜`$FFFF` を読むときは /ROMSEL を L にする（`P` `V` `B P` `D` は自動で行う）。

## `T`：データバス折り返し試験 [v4]

U5/U6（595）からデータバスへ値を出し、U7/U8（165）で読み戻す。カセットがなくても、データ系の経路（SCK・MOSI・MISO・/PL・RCLK_DATA・OE_DATA_N、595/165/U10、CPU D・PPU D の 16 本）をまとめて確認できる。

```
write CPU=00 PPU=FF  read CPU=00 PPU=FF OK
write CPU=FF PPU=00  read CPU=FF PPU=00 OK
write CPU=55 PPU=AA  read CPU=55 PPU=AA OK
  …（0xAA、ウォーキング 1 の 0x01〜0x80）
LOOPBACK OK
```

- PPU 側には CPU 側の反転パターンを出すので、CPU D と PPU D の間の短絡も検出できる
- プルアップ（R1〜R16）は VCC_CART に吊っているので、**`O 1` の後に実行する**
- 制御線は非アクティブのまま行うので、カセットが挿さっていてもカセットはバスを駆動しない
- NG のときは最後の行に `LOOPBACK NG  bad bits: CPU D=xx  PPU D=xx` と、異常のあったビットを表示する

## `S`：バス駆動タイミング [v4.1]

```
S             → 現在値を表示
S 125 500     → シフトクロック半周期 125 ns、アクセス待ち 500 ns
```

応答例：`shift clock half-period = 125 ns (4000 kHz), access wait = 500 ns  [clk_sys 133 MHz]`

| 設定 | 既定値 | 下限 | 意味と根拠 |
|---|---|---|---|
| シフトクロック半周期 | 125 ns（4 MHz） | 20 ns | 165 の QH は CLK 立ち上がりから t<sub>pd</sub> 最大 40 ns で変化する（CD74HCT165、V<sub>CC</sub> 4.5 V、−40〜85 °C）。1T45 と RP2040 の入力同期を足しても、半周期 2 回分（250 ns）あれば十分。f<sub>MAX</sub> は最小 22 MHz |
| アクセス待ち | 500 ns | 50 ns | アドレス確定（RCLK）・/ROMSEL または /RD を L にしてから 165 に取り込むまでの時間。マスク ROM のアクセス時間（150〜250 ns 程度）に余裕を持たせた値 |

**読み出しが不安定なカセットでは、まず `S 125 1000`（アクセス待ちを延ばす）、次に `S 500 1000`（クロックを下げる）を試す。** 設定は電源を切るまで保持される。

## `V`：ベクタ読み出し

```
NMI   $FFFA = $8082 [OK]
RESET $FFFC = $8000 [OK]
IRQ   $FFFE = $FFF0 [OK]
```

（スーパーマリオブラザーズの実測値）

| 表示 | 意味 |
|---|---|
| `[OK]` | `$8000`〜`$FFFE` の値 |
| `[NG] open bus (no data from cart)` **[v4]** | `$FFFF`。データバスがプルアップのまま＝カセットが何も出力していない（未挿入・接触不良・/ROMSEL 系の不良） |
| `[NG]` | `$8000` 未満 |

6502 は電源投入時に `$FFFC`/`$FFFD` を読んで開始番地とするため、正常なカセットなら値は必ず `$8000` 以上になる。

## `M`：ミラーリング判定

PPU アドレスを `$2000`、`$2400`（PA10 = 1）、`$2800`（PA11 = 1）の順に出力し、カセットが返す CIRAM A10 を読む。

| CIRAM A10 の追従先 | 判定 | 表示 |
|---|---|---|
| PA10 | 垂直ミラー | `VERTICAL (follows PA10)` |
| PA11 | 水平ミラー | `HORIZONTAL (follows PA11)` |
| どちらでもない | 1 画面 / 4 画面 / 配線異常 | `UNKNOWN (1-screen / 4-screen / wiring fault)` |

応答例：`CIRAM A10: base=0 PA10=1 PA11=0 -> VERTICAL (follows PA10)`

## `B`：ブロック読み出し [v4.1]

PC 側スクリプト（`tools/dump_nes.py`）が使う。シリアルモニタで送るとバイナリがそのまま表示されて画面が乱れる。

### 要求

```
B P aaaa nnnn     PRG（CPU $8000〜$FFFF）
B C aaaa nnnn     CHR（PPU $0000〜$1FFF）
```

| 引数 | 内容 |
|---|---|
| `aaaa` | 開始アドレス（16 進）。PRG は `8000`〜、CHR は `0000`〜 |
| `nnnn` | バイト数（16 進）。1〜`8000`（32 KB）。範囲外は `ERR range` |

### 応答

```
BLK n=<バイト数> crc=<8桁16進> us=<読み出し時間 µs>\n
<n バイトのバイナリ>
```

| フィールド | 内容 |
|---|---|
| `n` | 続くバイナリのバイト数 |
| `crc` | そのブロックの CRC-32（IEEE 802.3、zlib と同一） |
| `us` | カセットからの読み出しにかかった時間（USB 転送を含まない） |

- ファームは指定範囲を RAM（最大 32 KB）に読み込んでから送る
- PC は受信データの CRC を照合し、合わなければ同じブロックを再要求する（`dump_nes.py` は最大 3 回）
- 大容量カセット（マッパー対応）では、バンクを切り替えながらこのコマンドで 8〜32 KB ずつ読む想定

### 速度（スーパーマリオブラザーズ、既定タイミング、設計値）

| 対象 | 1 バイトあたり | 読み出し時間 |
|---|---|---|
| PRG 32 KB | 約 7 µs（CPU アドレス 16 bit を送る、165 は CPU D の 8 bit だけ読む） | 約 0.23 s |
| CHR 8 KB | 約 13 µs（アドレス 32 bit を送る、165 は 16 bit 読む） | 約 0.1 s |

v4.0（1 µs 刻みのビットバング）では 40 KB の吸い出し 1 回に 6.3 s かかっていた。

**PRG 読み出しの注意。** PRG は CPU アドレス（U1/U2）だけを書き換えるため、U3/U4（PPU アドレス）には直前の値が押し出されて入る。PPU /RD = 1 なので CHR 側は出力しないが、PPU アドレスの値を監視するマッパー（MMC2/MMC4 など）に対応するときは、PPU アドレスも明示的に設定する読み方に切り替える。

## `W` / `X`：書き込み [v4.2]

マッパー対応は「ファームは読み書きの基本操作だけ、マッパーごとの手順は PC スクリプト」に分けている。新しいマッパーはスクリプトの追加だけで対応できる。

### `W`：CPU 書き込みのタイミング

| 順 | 動作 |
|---|---|
| 1 | 制御線を非アクティブにし、U5（CPU D）にデータ、U1/U2 にアドレス（A0〜A14）をラッチ |
| 1a **[v4.3]** | ダミー読み出し：R/W = 1、/ROMSEL = 1 のまま M2 = 1（`acc`）→ M2 = 0 → `clk` 待ち |
| 2 | R/W = 0 → `clk` 待ち → `OE_DATA_N` = 0（データ出力） |
| 3 | M2 = 1、アドレスが `$8000` 以上なら /ROMSEL = 0 → `acc` 待ち |
| 4 | /ROMSEL = 1、M2 = 0（**ここでマッパーがデータを取り込む**）→ `clk` 待ち |
| 5 | `OE_DATA_N` = 1 → `clk` 待ち → R/W = 1 |

- 1a は MMC1 対策。MMC1 は直前の M2 サイクルも書き込みだと、その書き込みを無視する（`INC $8000` 等の RMW 命令対策）。ダンパーは `W` の間に M2 を出さないので、v4.2 では 5 回のシリアル書き込みのうち 1 回目しか届かなかった
- 実機 CPU と同じく、データは M2 の立ち下がりより前から確定し、R/W はその後に戻す（ホールド時間を確保）
- `$6000`〜`$7FFF`（PRG-RAM）は /ROMSEL を下げない。**バッテリーバックアップ付きカセットの `$6000`〜`$7FFF` には書かないこと**（セーブデータが消える）
- 書き込み 1 回あたり、USB の往復込みで約 0.1〜1 ms（PC の USB スケジューリングに依存）

### `X`：PPU 書き込み

PPU アドレス（A0〜A12、/A13 = 1）と U6（PPU D）をラッチ → `OE_DATA_N` = 0 → /WR = 0（`acc`）→ /WR = 1 → `OE_DATA_N` = 1。CHR-ROM のカセットでは ROM に /WE がないので何も起きない（PPU /RD = 1 なので ROM の出力ともぶつからない）。

### バス競合（UNROM / CNROM）

UNROM・CNROM はレジスタの書き込み中も ROM が出力しているため、書いた値と ROM の値がぶつかる（実質 AND になる）。スクリプトは**書きたい値と同じ値が ROM に入っている番地**を探して、そこに書く。MMC1・MMC3 は ROM の出力を止めるので競合しない。

## `D`：バイナリダンプ（v3 互換）

`dump_nes.py --legacy` が使う。

```
DUMP prg=<PRGサイズ> chr=<CHRサイズ> mir=<V|H|?>\n
<PRGデータ（prgバイト）>
<CHRデータ（chrバイト）>
\n
END crc=<8桁16進>\n
```

| フィールド | 内容 |
|---|---|
| `prg` | 16384 または 32768（前半と後半が一致すれば 16 KB 品と判定し、`$C000` 側を送る） |
| `chr` | 8192（固定） |
| `mir` | `V`（垂直）、`H`（水平）、`?`（判定不能） |
| `crc` | PRG と CHR を連結したものの CRC-32 |

## PC 側の処理（`tools/dump_nes.py` v3.1）

1. RP2040 のポートを自動検出（VID `0x2E8A`）。`--port` で指定も可
2. ポートを開く（**DTR = ON**、`timeout` は開くときに一度だけ設定）
3. `O 1`
4. 1 回目：`--mapper` で指定したマッパーの手順（下表）で PRG・CHR を読む（ブロック CRC NG なら再送）
5. 2 回目：同じ
6. `O 0`（エラーで中断した場合も必ず送る）
7. 2 回の結果（PRG、CHR、ミラーリング）が完全一致した場合のみ保存

### マッパーごとの手順

| マッパー | 容量の判定 | PRG | CHR |
|---|---|---|---|
| 0 NROM | PRG 前半＝後半なら 16 KB | `B P 8000 8000` | CHR-RAM 判定 → `B C 0000 2000` |
| 2 UNROM | 切替バンク i が固定バンク（`$C000`）と一致したら i+1 バンク（最大 16 = 256 KB） | 固定バンク内の値 i の番地に `W` → `B P 8000 4000` | CHR-RAM 判定（通常 RAM） |
| 3 CNROM | CHR バンク 4・8… が 0・1 と一致したら折り返し（最大 32 KB） | `B P 8000 8000` | PRG 内の値 i の番地に `W` → `B C 0000 2000` |
| 1 MMC1 | PRG：固定バンクと一致（最大 256 KB）、CHR：折り返し（最大 128 KB） | `W 8000 80`（リセット）→ 制御 `$1E` → `$E000` に i を 5 回書き → `B P 8000 4000` | `$A000` に i → `B C 0000 1000` |
| 4 MMC3 | PRG：固定バンク（`$E000`）と一致（最大 512 KB）、CHR：折り返し（最大 256 KB） | `W 8000 06` `W 8001 i` → `B P 8000 2000` | `W 8000 00` `W 8001 2i` → `B C 0000 0800` |
| 206 Namco 108 | MMC3 と同じ手順（PRG 最大 128 KB、CHR 最大 64 KB） | `W 8000 06` `W 8001 i` → `B P 8000 2000` | `W 8000 00` `W 8001 2i` → `B C 0000 0800` |
| 22 VRC2a | PRG：固定バンク（`$E000`）と一致（最大 256 KB）、CHR：折り返し（最大 128 KB） | `W 8000 i` → `B P 8000 2000` | `W B000 (2i)&F` `W B002 (2i)>>4` → `B C 0000 0400` |

- **Namco 108 系**のミラーリングは基板で固定なので `M` の結果を使う。**VRC2a** は CPU A0/A1 が入れ替わって配線されているので、CHR0 の上位は `$B001` ではなく `$B002`。また CHR バンク値の最下位ビットを無視するので 2 倍した値を書く
- Namco 108 系・VRC2a のバス競合はないものとして書いている。もし競合があればバンク切替が崩れて容量判定が成立しないので、誤ったデータは保存されずに止まる
- **CHR-RAM 判定**：`$0000`〜`$0007` に反転値を `X` で書いて読み戻し、反転していれば RAM（元の値に戻す）。RAM なら CHR は保存しない（iNES ヘッダの CHR = 0）
- **ミラーリング**：NROM・UNROM・CNROM は `M` の結果。MMC1・MMC3 はマッパーが切り替えるので、ヘッダには `H` を入れる（エミュレータはマッパー側の設定を使う）
- MMC1 の PRG 512 KB（SUROM）、MMC3 の 4 画面（TVROM 等）は未対応

### 生成する iNES ヘッダ（16 バイト）

| オフセット | 値 | 内容 |
|---|---|---|
| 0〜3 | `4E 45 53 1A` | `"NES"` + `$1A` |
| 4 | PRG サイズ ÷ 16384 | 1〜32 |
| 5 | CHR サイズ ÷ 8192 | 0（CHR-RAM）〜32 |
| 6 | マッパー下位 4 bit × 16 ＋ ミラーリング | bit 0 = 1 で垂直、上位 4 bit = マッパー番号下位 |
| 7 | マッパー上位 4 bit | 0〜4 では `$00` |
| 8〜15 | `$00` | 未使用 |

表示する CRC32 は PRG、CHR、PRG+CHR（ヘッダなし）の 3 つ。NesCartDB の ROM Details の PRG0 / CHR0 / ROMs Combined と照合する。スーパーマリオブラザーズの実測値は PRG+CHR `D445F698`。

### 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | ポートが見つからない、応答なし、電源 NG、転送エラーが再送しても直らない |
| 2 | 2 回のダンプが一致しない（接点の清掃を促す） |

## PC 側の実装上の注意（rev2 立ち上げで判明）

| 事象 | 原因 | 対策 |
|---|---|---|
| ファームの送信データが途中で欠ける | arduino-pico の `Serial.write()` は PC 側の受信が 1 秒以上止まると打ち切り、書けたバイト数だけを返す（`SerialUSB.cpp`） | ファームは戻り値を見て残りを送り直す（`writeAll()`） |
| 受信データが数十〜百バイト欠ける（Windows） | 受信中に pySerial の `timeout` を変更すると `SetCommState` が発行される | `timeout` はポートを開くときに一度だけ設定し、待ち時間はスクリプト側の締め切りで管理する |
| 何も受信できない | DTR が OFF だと arduino-pico は送信データを捨てる | ポートを DTR = ON で開く |
